# Request-charge evidence audit

Status: reviewed against the configured first-party source bundles; live sources refreshed on 2026-09-05.

This register covers all 18 configured providers and the request-charge mechanisms admitted by their current guides. The linked provider guides define exact source ownership, joins, protocol fields, exclusions, and claim-local drift behavior. Reviewed provider inputs live under `tests/fixtures/`; `tests/adapters.test.ts` and `tests/pricing-adapter.test.ts` exercise numeric, missing-field, unsupported, and conflicting cases. The calculation export retains evidence references and explicit gaps instead of claiming that token-rate coverage completes an operation.

A normalized rate establishes a public amount. A semantic binding additionally establishes a quantity and aggregation boundary. Acquisition additionally identifies a first-party field for every input of at least one method. Each level can exist without the next. Rows below distinguish supported mechanisms from remaining missing prices, measurements, selectors, or unsupported structures. “No separate charge” applies only where the reviewed provider contract establishes that disposition; absence of a published price remains unknown.

The machine-readable `/pricing/calculation/coverage.json` enumerates every accepted logical component, including unbound and raw terms, its operation predicates, binding/acquisition counts, missing selector mappings, source references, and freshness. Use it for snapshot-specific coverage; this register deliberately avoids volatile model counts and prices.

## Shared decisions and acceptance

- Published minimums and billing increments are quantity operations applied at an explicit aggregation boundary. The shared `round_up` operation is implemented and tested, but raw provider billing blocks stay raw when their eligibility, rounding or reset boundary is incomplete. OpenAI container/search blocks and Anthropic minimum/monthly allowance are regression examples of this distinction.
- Cache partitions, reasoning inclusion, mixed media, context bands, currencies/credits, served tier, region, tools and duration retain their provider-specific measurement semantics. No universal absent-counter-to-zero rule exists.
- Additive service charges require an actual billable service component. Compatibility is not incidence. Contributions reference existing rates; allowances cannot double count, cross an unknown reset period, or invent allocation order.
- Every refreshed provider publishes atomically. A source-contract failure can remove only an affected input mapping when the remaining provider is valid; an invalid provider candidate retains its previous accepted partition and visible freshness. No source allowlist is widened to hide a failed refresh.
- Provider fixtures establish extraction and unresolved behavior. Portable synthetic conformance vectors independently exercise evaluator semantics; generated-data gates compare all exported provider terms with their canonical source. Package checks verify the packed Node/browser implementation has no real prices or transport.

Future work should resolve a listed gap only with first-party price, applicability, quantity and aggregation evidence. Update that provider guide and a reduced reviewed fixture together; replace the obsolete gap rather than appending historical conclusions. The current release prepares one TypeScript package and a portable contract, without registry publication or a second-language evaluator.
